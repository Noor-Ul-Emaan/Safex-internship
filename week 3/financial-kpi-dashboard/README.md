# Ledger — Financial KPI Analytics Dashboard

An MVP financial KPI dashboard built for an e-commerce retailer, so finance,
support, and management stakeholders can see revenue, expense, profit, and
budget performance in one place instead of scattered spreadsheets.

## The problem

An e-commerce retailer's finance metrics — revenue by product line, expenses
by category, and how actuals compare to budget — usually live in separate
spreadsheets that different people update on different schedules. Nobody has
one current view of "how is the business doing this month," and answering
that question means manually pulling and reconciling files. This project
builds a single, always-current dashboard that rolls up from order-level
data into KPI cards, trend charts, a budget-variance view, and a drill-down
into the underlying line items.

## Who it's for

Internal teams at the retailer — analysts who need the underlying numbers,
managers who need the monthly trend and budget picture, and support staff
who occasionally need to trace a KPI back to specific orders.

## What it does (features)

**Core**
- KPI summary cards: YTD revenue, YTD expense, YTD net profit, latest-month
  net margin, each with a month-over-month delta
- Monthly trend chart: revenue / expense / profit over the full year
- Revenue and expense visuals: revenue by product line (stacked, monthly)
  and expense composition for the latest month

**Advanced**
- **Variance-to-budget view**: monthly revenue/expense variance % against
  a budget plan, plus a line-item detail table for the latest month
- **Drill-down**: click a product line to see its monthly revenue trend and
  the top underlying orders (order id, date, channel, units, revenue)

## How it's built

```
financial-kpi-dashboard/
├── data/
│   ├── order_line_items.csv        # order-level "ground truth" data
│   ├── monthly_actuals.csv         # revenue/expense actuals by month & category
│   ├── monthly_budget.csv          # budgeted revenue/expense by month & category
│   └── ecommerce_financials.xlsx   # all three tables, one workbook (Excel view)
├── scripts/
│   ├── generate_data.py            # builds the synthetic dataset with numpy/pandas
│   └── kpi_analysis.py             # pandas: computes KPIs, trends, variance, drill-down
├── dashboard_data.js               # generated by kpi_analysis.py — the data the dashboard reads
├── dashboard.html                  # the dashboard itself (open directly in a browser)
└── requirements.txt
```

The pipeline is deliberately simple and reproducible: `generate_data.py`
creates order-level records the way a real order management system would,
`kpi_analysis.py` does the pandas aggregation (this is the layer that would
change if you plugged in a real SQL export instead of synthetic data), and
`dashboard.html` is a static, dependency-light front end (vanilla JS +
Chart.js) that reads the resulting `dashboard_data.js`. No server or
database is required — open `dashboard.html` in any browser.

### Running it yourself

```bash
cd scripts
pip install -r ../requirements.txt
python generate_data.py     # writes data/*.csv and data/*.xlsx
python kpi_analysis.py      # writes ../dashboard_data.js
```

Then open `dashboard.html` in a browser (it loads `dashboard_data.js`
alongside it).

### Swapping in real data

`kpi_analysis.py` expects three tables with this shape:

- `monthly_actuals.csv` / `monthly_budget.csv`: `month, type (revenue|expense), category, amount`
- `order_line_items.csv`: `order_id, date, month, product_line, channel, units, revenue, returned`

Point the script at real exports in that shape (e.g. a SQL query result or
an Excel export) and the rest of the pipeline — KPI cards, trend chart,
variance view, drill-down — updates automatically.

## Tools & technologies

Python (pandas, numpy), a static HTML/JS dashboard (Chart.js) in place of
Power BI/Looker Studio so the deliverable is self-contained and viewable
without a paid BI license, Excel (`.xlsx`) as the source-of-truth workbook
finance would actually receive, and SQL-shaped tabular data throughout so
the same pipeline works against a real warehouse export.

## Challenges & how they were solved

Building a believable variance-to-budget view required a budget dataset
that disagreed with actuals in a realistic way — a budget that matched
actuals exactly would make the variance view pointless. The budget table is
generated as the actuals plus randomized noise (~9% standard deviation) per
category per month, which produces the kind of over/under-budget swings a
real finance team would actually need to investigate, while still tying
back to the same categories as the actuals for a clean join.

## Skills used / learned

- Structuring a small data pipeline: raw transactional data → aggregated
  tables → a presentation layer, with a clear seam where real data could be
  substituted in
- pandas groupby/aggregation across multiple dimensions (month, category,
  product line) and merging actuals against budget for variance
- Designing KPI cards and charts around the questions a finance stakeholder
  actually asks (where are we vs. budget, what's driving revenue, can I see
  the orders behind a number)
- Building a dependency-light, static dashboard front end that a
  non-technical stakeholder can open without any setup
